## 为什么需要全局色调映射（GTM）
人眼对亮度的感知不是线性的：暗部一点点变化就很明显，亮部变化很大却不一定看得出来。显示设备、拍摄设备、存储格式也都有自己的“灰阶预算”。Gamma 校正就是用一条幂律曲线，把“线性光”映射到“看起来舒服的灰阶”。通常在$LTM$模块后。

基本公式：

$$ y = round(MAX \cdot (\frac{x}{MAX}) ^ \gamma \cdot e)$$

其中：x是输入像素，8 bit 时，MAX=255；y是输出像素；$\gamma$是曲线指数；e是曝光补偿系数。

当$\gamma \lt 1$：整体变亮；$\gamma = 1$：整体变亮：线性不变。

显示端的 sRGB 大约相当于$\gamma$=2.2。

如果要把线性光编码成 sRGB 显示信号，通常用 
$\gamma \approx$ 1 / 2.2 $\approx$ 0.45。

如果要把一个已经按 sRGB 编码的图像解码回线性光，才用 $\gamma \approx 2.2$。

关键是分清**编码方向**：显示器输入的 sRGB 数值不是线性亮度。可以粗略把显示器理解为：输入信号 \(S\) 会产生约 \(S^{2.2}\) 的光亮度。因此，要把线性亮度 \(L\) 转成显示信号，就要反向补偿显示器的响应，近似计算 \(S=L^{1/2.2}\)；反过来，若拿到已编码的 sRGB 信号，想还原成线性亮度，就近似计算 \(L=S^{2.2}\)。

补充一点：sRGB 的标准转换并非对所有数值都严格使用单一的 2.2 次方，而是分段曲线；“约 2.2”适合理解方向和大致关系。

## 硬件实现
在硬件中计算 $x^{0.45}$ 需要乘法器、开方或对数近似以及流水线，面积和功耗都不划算。由于输入是 8 bit，只有 256 种可能，因此可以预先计算全部 256 个结果并存入 RAM：


### 优点

- 每个周期查表一次，可达到 1 pixel/cycle 的吞吐率。
- 曲线可以是任意形状，不必局限于幂函数。
- R、G、B 三个通道可以独立配置，便于做白平衡或风格化处理。

### 代价

- 需要 3 块 $256 \times 8$ bit 的 RAM。
- 曲线通常只能在帧间更新。
- 如果输入位宽增加到 10 bit 或 12 bit，256 项 LUT 就不够，需要插值或使用更大的 LUT。


## 附录


### 调参顺序


第一步，确定目标 Gamma

- 只做显示编码：$\gamma \approx 1/2.2 = 0.4545$。
- 想提亮暗部：减小 $\gamma$，例如从 $0.4$ 调到 $0.45$。
- 想压暗、增加对比：增大 $\gamma$，例如调到 $0.5 \sim 0.6$，或按需求调整。
- 需要曝光补偿：在公式里乘以 $e$，再执行 `clip(0, 255)`。

第二步， 生成 LUT

```python
import numpy as np

def gamma_lut(gamma=0.45, exposure=1.0):
    x = np.arange(256, dtype=np.float64)
    y = np.round(255 * (x / 255) ** gamma * exposure)
    return np.clip(y, 0, 255).astype(np.uint8)
```

检查：

- LUT 是否单调不减；
- `0` 是否映射到 `0`（除非有意抬黑）；
- `255` 是否映射到 `255`（除非有意压高光）；
- 相邻节点差是否过大（可能出现 banding）；
- 三个通道是否平衡（白平衡）。

第三步，写入顺序

1. 关闭 GTM（或至少在帧间更新）。
2. 写入 256 个地址 × 3 个通道。
3. 确认写完后，再使能 GTM。
4. 一帧内不要修改 LUT。

如果 APB 一次只能写一个通道，需要使用 read-modify-write，或者用影子寄存器在帧间原子切换。
